# Tile Downloader

Приложение на Python для скачивания тайлов спутниковых карт с Яндекс Карт и их
хранения в локальной базе данных SQLite для автономного доступа.

Работает в **клиент-серверной** архитектуре: один сервер владеет мастер-БД и
раздаёт задачи, а множество клиентов (процессов/машин) параллельно скачивают
свои диапазоны тайлов и сдают их серверу. Никакой тайл не выдаётся двум клиентам
одновременно, повторные сабмиты идемпотентны, а прогресс переживает падение и
сервера, и клиентов.

## Особенности

- 🌐 **Параллельная загрузка**: несколько клиентов на разных машинах докачивают
  одну базу без повторного скачивания одних и тех же тайлов.
- 💾 **Единая мастер-БД**: сервер владеет `tiles_N.db3` (формат не менялся:
  одна таблица `zN` на зум, PK `(x, y)`, WAL).
- 🔄 **Возобновление и докачка**: сервер сам находит пропуски в существующих
  `tiles_N.db3`; `settings.pickle` больше не нужен.
- 🛡️ **Отказоустойчивость**: локальный буфер клиента переживает его падение;
  TTL + heartbeat освобождают задачи «молчаливо» умерших клиентов; рестарт
  сервера безопасен (запись идемпотентна).
- 📊 **HTML-дашборд**: текущий зум и общий процент, прогресс по слоям, клиенты
  с их состояниями (ждёт задание / отрабатывает / отдаёт результат) и скорость
  приёма — без внешних зависимостей.
- ⚡ **Асинхронность**: asyncio + aiohttp; бинарный (не JSON) протокол сабмита.

## Требования

- Python 3.8+
- `aiohttp`

## Установка

```bash
git clone <ссылка-на-репозиторий>

```

## Использование

### 1. Запустить сервер

```bash
# Windows
server\server.bat
# Linux/macOS
./server/server.sh
```

По умолчанию сервер слушает `0.0.0.0:31059`, каталог мастер-БД — `./master`,
зум-диапазон `1..14`. Дашборд: <http://localhost:31059/dashboard>.

Полный список аргументов — `python server.py --help`:

| Аргумент | Описание | По умолчанию |
|----------|----------|--------------|
| `-o, --output-dir` | Каталог мастер-БД и `jobs.db3` | `.` |
| `--host` / `--port` | Адрес и порт HTTP | `0.0.0.0` / `31059` |
| `--min-zoom` / `--max-zoom` | Диапазон зумов | `1` / `14` |
| `-z, --zoom` | Скачивать только зум N | — |
| `--chunk-size` | Размер задачи (тайлов) | `2000` |
| `--task-ttl` | Время жизни задачи без heartbeat, c | `900` |
| `--reap-interval` | Период TTL-рипера, c | `15` |
| `--idle-window` | Молчание клиента дольше, c (статус «неактивен») | `15` |

### 2. Запустить один или несколько клиентов

```bash
# Windows
client\client.bat --server http://<host>:31059
# Linux/macOS
./client/client.sh --server http://<host>:31059
```

Каждый клиент: получает задачу (`GET /api/task`), скачивает свой диапазон тайлов
(N потоков, ретраи), пишет их в локальный буфер, сдаёт серверу бинарным фреймом
(`POST /api/tasks/{id}/submit`) и повторяет, пока сервер не сообщит `done`.

Аргументы клиента — `python client.py --help`:

| Аргумент | Описание | По умолчанию |
|----------|----------|--------------|
| `--server` | URL сервера | `http://127.0.0.1:31059` |
| `--client-id` | Идентификатор клиента | имя хоста |
| `--buffer-dir` | Каталог локального буфера | `./buffer` |
| `--threads` | Потоков на скачивание | `16` |
| `--tile-url` | Шаблон URL тайла (`{x}`,`{y}`,`{z}`) | Яндекс Карт |
| `--heartbeat-interval` | Период heartbeat, c (`0` — выкл) | `300` |
| `--retry-delay` | Пауза между ретраями, c | `30` |
| `--once` | Одна задача и выход | — |

Несколько клиентов = несколько запусков `client.py` с разными `--client-id`
(на разных машинах или на одной). Сервер сам координирует диапазоны.

## Как это работает

1. **Сервер** открывает/создаёт мастер-БД и `jobs.db3`, находит первый недостающий
   тайл в активном зуме и выдаёт клиенту диапазон индексов `[start_idx, end_idx)`.
2. **Клиент** скачивает тайлы диапазона параллельно, пишет каждый в локальный
   SQLite-буфер (точка устойчивости) и одним бинарным фреймом сдаёт серверу.
3. **Сервер** записывает тайлы в мастер-БД (`INSERT OR IGNORE`), увеличивает
   счётчик зума, а остаток диапазона (не присланные тайлы) возвращает в пул.
4. Когда зум докачан — сервер переходит к следующему; когда всё готово —
   клиенты получают `done: true` и завершаются.

Задачи, не сданные в срок (`task-ttl`) и не продлённые heartbeat-ом,
освобождаются фоновым TTL-рипером и выдаются другим клиентам.

## Структура проекта

Проект разделён на два независимых подпроекта; каждый самодостаточен и
разворачивается отдельно (нужен только `aiohttp`).

- **`server/`** — сервер заданий:
  - `server.py` — HTTP-сервер (aiohttp) + TTL-рипер
  - `jobs.py` — ядро: выдача задач, учёт in-flight, TTL, статистика
  - `db.py` — доступ к мастер-БД (`Repository`)
  - `dashboard.py` — HTML-дашборд (инлайн-стили/JS)
  - `migrate.py` — миграция legacy `tiles.db3` в per-zoom базы
  - `protocol.py`, `utils.py` — общие модули (своя копия)
  - `server.bat` / `server.sh`, `install.bat`, `requirements.txt`
- **`client/`** — клиент-рабочий:
  - `client.py` — загрузка диапазона, буфер, сабмит, heartbeat
  - `buffer.py` — локальный SQLite-буфер
  - `protocol.py`, `utils.py` — общие модули (своя копия)
  - `client.bat` / `client.sh`, `install.bat`, `requirements.txt`
- **`tests/`** — общие тесты (импортируют модули из `server/` и `client/`)
- `reduce.py` — поиск дублей в мастер-БД (автономный инструмент, остаётся в корне)

> `protocol.py` и `utils.py` намеренно продублированы в обоих проектах —
> при изменении правьте обе копии (либо держите их синхронными).

## Хранение данных

- Каждый зум — отдельная БД `tiles_N.db3`, таблица `zN` со схемой
  `(x, y, image, ext)`, PK `(x, y)`, режим WAL.
- Состояние сервера — `jobs.db3` (задачи, метаданные, события, статистика).
- Локальный буфер клиента — `buffer_<client_id>.db3`.
